# 冒險模式（Adventure Mode）設計規格

- 日期：2026-10-05
- 狀態：設計已確認，待撰寫實作計畫
- 適用：`workspace/`（網頁版與 iOS 版共用同一份原始碼）

## 1. 背景與目標

iOS 版 v1.0 (build 3) 於 2026-10-01 被 App Store 以 **Guideline 4.3(a) Design – Spam** 退件：
概念與其他開發者的 App 相近、只有細微差異。目前遊戲本質上就是 Just Get 10 類玩法加上生涯獎盃。

目標：加入一個有明顯差異的 **roguelite 回合制戰鬥模式**，作為遊戲主打內容，
讓「湊 10」成為魔法師的攻擊手段，藉此重新送審。網頁版同步獲得此模式。

非目標（本版不做）：
- 屬性／元素相剋（已討論，判定為時過早）
- 分支路線地圖
- 永久數值升級樹、局外貨幣
- 多位可選角色

## 2. 模式結構

- 首頁新增模式選單：**冒險**（主要、預設）／**修練**（現有無盡模式，行為完全不變）。
- 網頁版與 iOS 版都提供兩種模式。
- Game Center、StoreKit 等原生功能沿用現有的 `window.Capacitor` 判斷，不影響網頁版。

## 3. 戰鬥規則（回合制）

### 3.1 基本循環

滑動一次 = 一回合。每回合依序：

1. 執行滑動與消除（沿用 `grid.ts` 規則：相鄰兩格加總為 10 即消除）。
2. 結算傷害與魔力。
3. 處理石塊碎裂（見 3.4）。
4. 敵人意圖倒數 -1；歸零則執行意圖，並進入下一個意圖。
5. 生成新數字（套用預防層策略，見 4.1）。
6. 檢查卡死，必要時觸發魔力暴走（見 4.3）。
7. 檢查勝負：敵人血量 ≤ 0 → 勝利；魔法師血量 ≤ 0 → 失敗。

若滑動無效（盤面沒有任何改變），不算一回合，敵人不行動。

### 3.2 數值（初稿，之後依試玩調整）

| 項目 | 數值 |
|---|---|
| 盤面大小 | 4×4（與修練模式相同） |
| 魔法師初始血量 | 10 |
| 每消除一對 | 10 傷害、+1 魔力 |
| 連鎖（同一步消除 ≥ 2 對） | 該步每對傷害 ×1.5（取整數，無條件捨去） |
| 普通敵人血量 | 40～80 |
| Boss 血量 | 150～250 |

### 3.3 失敗條件

唯一的失敗條件是**魔法師血量歸零**。盤面滿了不會直接結束（見第 4 節）。

### 3.4 特殊格子

| 格子 | 表示方式 | 規則 |
|---|---|---|
| 石塊 | 特殊值 `STONE` | 不能與任何數字湊成 10；會隨滑動移動；當上下左右相鄰的格子在本回合被消除時，石塊碎裂 |
| 冰凍 | 盤面之外另存一個冰凍遮罩（帶剩餘回合數） | 被冰凍的格子不能移動，滑動時視為牆；格子仍可參與消除；剩餘回合數歸零時解凍 |
| 0 | 數值 `0` | 不需特別處理：0 加上 1～9 永遠不等於 10，天生湊不出來；只能用法術清除 |

## 4. 防卡死三層機制

### 4.1 第 1 層：預防（玩家看不到）

`spawnRandomTile` 新增可選的生成策略參數。冒險模式的策略：
當空格數 < 4 時，有 50% 機率生成「某個鄰格數值的補數」（10 − 鄰格值），
且該生成位置要與這個鄰格相鄰。修練模式不傳參數，行為不變。

### 4.2 第 2 層：法術（玩家主動解）

現有的 4 種道具改成法術，消耗魔力施放。魔力每場戰鬥從 0 開始。

| 法術 | 效果 | 魔力 |
|---|---|---|
| 🔨 碎石 | 打掉一格（數字、石塊或 0 皆可） | 2 |
| ➕ 增幅 | 某一格數字 +1；若是 9 則直接消除該格，視同消除一對（10 傷害、+1 魔力）。與修練模式一致。不能對石塊施放 | 2 |
| 💣 爆裂 | 清掉目標格及其上下左右共 5 格（十字形，與修練模式一致） | 4 |
| 🔀 洗牌 | 重新排列盤面上所有已佔用格子的內容（石塊、0 一起參與）；冰凍格不參與 | 3 |

施法不算一回合，敵人不行動。法術效果沿用修練模式的道具實作（見 9.2）。

### 4.3 第 3 層：魔力暴走（保底）

觸發條件：盤面沒有任何有效滑動，**且**目前魔力不足以施放任何法術。

效果：
- 魔法師扣 2 血。
- 盤面隨機清除一半的已佔用格子（無條件捨去），清除時忽略冰凍。
- 敵人意圖倒數照常 -1。

扣血可能使血量歸零，此時判定為失敗（屬於被擊敗，而非盤面滿了）。

## 5. 敵人

### 5.1 意圖（5 種）

每種敵人有**固定的行動循環**，畫面上會顯示目前的意圖和倒數回合數。

| 意圖 | 效果 |
|---|---|
| ⚔ 攻擊 N | 扣魔法師 N 血 |
| 🪨 落石 K | 在 K 個隨機空格放置石塊（空格不足就放滿為止） |
| ❄ 冰凍 | 隨機凍住一個有數字的格子 3 回合 |
| 🛡 護盾 N | 敵人獲得 N 點護盾，護盾先吸收傷害，可累加 |
| 🌀 擾亂 | 隨機一格數字 ±1（結果維持在 1～9） |

### 5.2 敵人陣容（9 種，簡約幾何風，用 Canvas 繪製）

| 區域 | 普通敵人 1 | 普通敵人 2 | Boss |
|---|---|---|---|
| 森林 | ⚪ 圓史萊姆（攻擊） | 🟫 方塊石像（落石） | 🔺 三角樹王：攻擊、落石交替 |
| 冰窟 | ❄ 雪花精（冰凍） | 💎 菱晶盾衛（護盾） | ⬡ 六角冰后：冰凍、護盾交替 |
| 魔王塔 | 🌀 螺旋術士（擾亂） | ⬛ 暗影方陣（綜合） | ⭕ 零之魔王 |

**零之魔王**的專屬意圖「歸零」：把隨機 2 格數字變成 0。
各敵人的血量、行動循環、倒數長度的具體數值，在實作計畫中定案，並集中放在 `enemies.ts`。

## 6. 一局的流程

- 3 區 × 3 場 = **9 場戰鬥**，單線路徑：普通 → 普通 → Boss。
- 目標時長：一局 15～20 分鐘。
- 血量跨戰鬥保留；盤面、魔力、冰凍、護盾每場戰鬥重置。
- 普通戰鬥勝利後三選一：遺物／法術強化／回 3 血（不超過血量上限）。
- Boss 戰勝利後：保證獲得一個遺物（三選一），並回復一半血量上限（無條件捨去）。
- 打倒零之魔王 → 通關。血量歸零 → 本局結束，顯示到達層數。

法術強化的具體內容（例如減少魔力消耗、擴大範圍）在實作計畫中定案，初版 4 個法術各 1 級強化即可。

### 6.1 存檔

- 每回合結束後，把整局狀態序列化存到 localStorage（key：`mathMerge10AdventureRun`）。
- 存檔格式帶版本號；版本不符或資料損毀時，捨棄存檔並回到首頁，不可讓遊戲崩潰。
- 首頁偵測到進行中的存檔時，顯示「繼續冒險」。

## 7. 遺物

初版共 12 個：開局抽選池中有 6 個，另外 6 個靠冒險獎盃解鎖。
遺物以「修正值＋事件掛鉤」實作（例如 `onBattleStart`、`onPairCleared`、`onOverload`、`onStoneBroken`、`onBattleEnd`）。

已確定的 6 個（初始抽選池）：

| 遺物 | 效果 |
|---|---|
| 魔力水晶 | 每場戰鬥開始時魔力 +2 |
| 連鎖之戒 | 連鎖倍率由 ×1.5 變為 ×2 |
| 生命之杖 | 每場戰鬥勝利後回 2 血 |
| 暴走之心 | 魔力暴走時不扣血，改為對敵人造成 20 傷害 |
| 補數護符 | 預防層在任何空格數下都有 30% 機率生效（與 4.1 取較高者） |
| 石匠手套 | 每碎一塊石塊，對敵人造成 5 傷害 |

另外 6 個要解鎖的遺物，在實作計畫中設計，每一個對應一個冒險獎盃。

## 8. 解鎖（輕量 roguelite）

- 沿用現有的生涯獎盃系統，新增一組「冒險獎盃」（例如：擊敗三角樹王、首次通關、單場觸發 3 次暴走並獲勝）。
- 每拿到一個冒險獎盃，就解鎖一個對應的遺物，加入抽選池。
- 沒有其他局外成長。

## 9. 程式架構

### 9.1 原則

- 規則全部寫成純函式，亂數用注入的 `Rng`（與 `grid.ts` 一致）。
- 新功能放在 `src/adventure/`，不再擴大 `game.ts`。
- 修練模式的行為與現有測試必須維持不變。

### 9.2 現有程式的擴充

| 位置 | 變更 |
|---|---|
| `grid.ts` `spawnRandomTile` | 新增可選的生成策略參數；預設行為不變 |
| `grid.ts` `slide` | 新增可選的冰凍遮罩；被凍住的格子視為牆 |
| `grid.ts` | 新增 `STONE` 常數；確保它不會與任何數字湊成 10 |
| `game.ts` → `powerups.ts` | 把 `applyHammer`、`applyShuffle`、`applyAddOne`、`applyBomb` 抽成純函式，修練與冒險共用 |
| `game.ts` → `boardRenderer.ts` | 把盤面繪製與動畫（`render`、`drawBaseTile`、消除動畫）抽出共用；只改結構不改行為 |
| `trophies.ts` | 新增冒險獎盃，以及獎盃→遺物的解鎖對應 |
| `index.html` | 模式選單、冒險畫面的 DOM |

### 9.3 新模組 `src/adventure/`

| 檔案 | 職責 |
|---|---|
| `battle.ts` | `applyTurn(state, direction, rng)` → `{ state, events }`；`castSpell(...)`；暴走判定；勝負判定 |
| `intents.ts` | 5 種意圖＋「歸零」的效果函式 |
| `enemies.ts` | 9 種敵人資料（血量、行動循環、形狀、顏色） |
| `relics.ts` | 12 個遺物定義與事件掛鉤 |
| `run.ts` | 戰鬥順序、三選一抽獎、血量延續、存讀檔 |
| `view.ts` | 冒險畫面：幾何怪物、血條、護盾、意圖標示、法術列、三選一視窗 |

`events` 是畫面層用來播放動畫和音效的事件列表（例如 `pairCleared`、`damageDealt`、`intentFired`、`overload`），
規則層不直接操作 DOM 或 Canvas。

## 10. 測試

- **單元測試（vitest）**：戰鬥結算、連鎖、意圖、特殊格子、三層防卡死、遺物效果、三選一、存讀檔（含損毀資料），全部使用固定亂數種子。
- **e2e（playwright）**：開發模式支援 `?seed=` 固定亂數；自動完成至少一場完整戰鬥，以及從首頁進入兩種模式。
- 現有的全部單元測試與 e2e 測試必須維持通過；`boardRenderer.ts` 重構前後都要執行 `merge-animation`、`visual-effects` e2e。

## 11. 分階段

### P1：可送審版
1. `boardRenderer.ts` 重構（先做，風險最高）
2. 道具效果抽成純函式；`grid.ts` 擴充（生成策略、冰凍遮罩、石塊）
3. 戰鬥核心、意圖、三層防卡死
4. 9 種敵人、4 個法術與強化、12 個遺物
5. 一局的流程、存讀檔
6. 冒險獎盃與解鎖
7. 模式選單；iOS 執行 `sync-web` 並在模擬器上驗證

### P2：打磨
- Game Center 冒險排行榜（需在 App Store Connect 新增）
- 自動模擬平衡腳本
- 特效、音效
- App Store 截圖與描述改為主打冒險模式
